## Результат и модели
Получилось добиться скора 0.8 на LB с помощью RandomForest, мета модель дала не особо выделяющиеся результаты, но возможно надо было лучше подобрать к ней параметры. В по обучению, из за того то датасет маленький я не запаривался с отбором признаков, а сосредочился чисто на FE и отборе гиперпараметров модели. Самый крутой признак который дал очень большой прирост к результату это Initail, на мой взгляд он идеально кодирует ключевые данные каждого пассажира, а именно возраст и пол, что дает моделям очень хорошую информацию для предсказания.Так же я попробовал объединить предполагаемых членов одной семьи через признак FamilyID, придерживаясь гипотезы, что исходы родственников могут быть связаны. Для моделей без нативной обработки категориальных признаков я рассчитывал Family_TE — сглаженную долю выживших внутри группы FamilyID. На обучающей выборке использовал leave-one-out: исключал собственный исход пассажира из семейной статистики. Параметр m регулирует силу сглаживания к средней выживаемости обучающей части фолда: чем он больше, тем меньше влияние статистики конкретной семьи. Если других представителей семьи в обучающей части нет, признак равен средней выживаемости этой части. На валидации и тесте использовалась семейная статистика, рассчитанная только по обучающим данным. Не для всех моделей это дало хорошие резульаты, но у части по значению SHAP он был в топе по важности. Валидация у меня была CV 5 фолдов, с отложенным hold-out, что в целом показалось мне хорошим выбором. Тут я не особо столкнулся с какими то сложностями, датасет маленький, признаков мало, обработать их не сложно, учиться все быстро.

## Структура проекта и работа в ноутбуке (повторяется с структурой House prices)
Вообще я постарался написать максимально емкий пайплайн, который в дальнейшем будет легко дополнять. В целом структура на мой взгляд получилась достаточно понятная, описал ее в графике выше, мне было достаточно просто итерировать эксперименты, которые я по сути делал в три этапа для каждой модели (ручной подбор диапазонов через Grid Search, рисовал нужные на мой взгляд графики для того чтобы лучше понимать динамику изменений, затем подбор лучших гиперпараметров Optuna, затем отбор признаков SHAP (обсудил выше)), для удобства трекинга экспериментов добавил логирование в Mlflow. Мне удобнее почти все делать в ноутбуке, поэтому основным местом проведения экспериментов я выбрал его. Возможно стоило по-другому организовать main и он должен непосредственно являться местом запуска каждого эксперимента, но я так попробовал и мне не очень понравилось, поэтому я пока остановился на не слишком проработанном варианте, зато задал основу возможному расширению функционала пайплайна. С точки зрения API, я старался делать все максимально универсальным чтобы любая модель в API близким к sklearn могла спокойно обучаться, и для того чтобы можно было легко и просто расширяться, добавлять кастомные модели, особенно запарился с нейронкой в этом плане, с сетккинг риджом не так сильно, так как делал его в самом конце, поэтому он в мейне в отдельную функцию вынесен, хотя по-хорошему так же должен был быть в одном блоке со всеми. 


## Запуск проекта

Все команды выполняются из корня проекта.

1. Установите зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

2. В `config.py` укажите пути к данным, папке сохранения моделей и сабмитов.

3. В отдельном терминале запустите сервер MLflow:

   ```bash
   python -m mlflow server --port 5000
   ```

   Интерфейс экспериментов доступен по адресу: http://localhost:5000.
   Адрес сервера должен совпадать с `Config.experiment_uri`.
   Далее создайте эксперимент, имя эксперимента должно совпадать с указанным в Config.experiments_name

5. Запустите обучение:

   ```bash
   python main.py
   ```

   Скрипт обучает модели на кросс-валидации, сохраняет их и выводит итоговые метрики. Параметры, метрики и графики логируются в MLflow.

6. Для создания сабмитов запустите:

   ```bash
   python inference.py
   ```

   Скрипт загружает сохранённые модели, получает предсказания для тестовых данных и сохраняет CSV-файлы в `Config.path_to_submission`.

Основное место проведения ручных экспериментов — ноутбук проекта.
